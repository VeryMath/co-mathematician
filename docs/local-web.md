# 本地研究工作台

本地网页版与原 co-math CLI 共用项目文件。可以创建或打开项目，阅读 Markdown、数学公式和文本材料，与模型讨论，并把回答保存为新研究笔记。

## 启动

需要 Node.js 22.19 或更新版本，以及 Python 3.10 或更新版本。先用 Python 的 `--version` 确认版本，再安装当前项目及前端依赖：

```bash
python -m pip install -e .
npm install --package-lock=false
npm run check
npm run build
CO_MATH_PYTHON=python npm start
```

这里的 `python` 应是已安装 Core 依赖的 Python 3.10+ 命令或完整路径。Windows PowerShell 先运行 `$env:CO_MATH_PYTHON="python"`，再运行 `npm start`。本轮只在 macOS 上实际运行过。

默认地址为 `http://127.0.0.1:4175`。开发时使用 `npm run dev`，由同一 Node 服务提供 API 与 Vite 页面；开发模式修改前端后手动刷新，修改服务端后重启。运行日志只显示启动地址和必要错误。

## 项目和模型

1. 点击“新建 / 打开项目”。在“打开已有项目”中点击已打开过的研究即可继续；也可以点击“选择项目文件夹”，从项目位置、桌面或文稿逐层查找。找到项目后会自动显示项目名称，再点击“打开项目”。手动输入路径收在可选项中。普通论文或笔记文件夹可在新建研究后通过“添加材料”导入。
2. 新项目填写名称、研究问题和材料语言。默认项目目录沿用 Core 的 projects_home 设置。
3. 在“模型服务”选择服务、填写密钥、选择模型，然后点击“保存并使用”。华师大 ECNU 的地址已预填；选择“其他服务”时再填写服务商的基础地址。默认只展示这三项，名称和手动模型列表放在“更多设置”。
4. 点击“添加材料”或把文件拖到工作区。可以一次选多个文件；同名文件自动另存。添加后点击材料上的“结合此文档提问”。每轮自动发送 PROJECT.md，加上最多六份所选文档及最近对话。材料文字合计最多 22,000 字符，过长时分配开头节选并在回答来源中说明；历史最多 12 条、12,000 字符。
5. 输入问题并发送。服务端保存回答，刷新不会重新发起模型任务。点击“停止”取消当前请求并保留已生成的部分。
6. 使用“保存为笔记”写入 workspace/project/notes 下的新 Markdown 文件。左侧显示笔记标题，原有文件不会被覆盖。

历史优先保留最近一轮问答，再按剩余预算加入更早的完整轮次。最近一轮本身超过预算时，预算允许时完整保留短消息，需要节选的消息保留开头和结尾，中间明确标注省略，并在回答来源中提示历史节选。普通对话仍最多使用 12,000 字符，选择 Skill 时为 6,000 字符；保存在项目中的完整对话不变。若追问涉及被省略的推导，请重新提供相关段落。

目录与文档之间、文档与对话之间的竖向分隔线可拖动调整宽度；双击恢复默认，选中后也可用左右方向键微调。布局会在当前浏览器中记住，缩小窗口时自动保留可阅读的宽度；窄窗口仍使用材料/对话页签。

左侧“研究目标”会把项目中的 GOALS.yaml 展示成可读的研究问题、语言和目标列表；中文转义会还原显示，原始配置可按需展开。项目状态记录和 Skill 内部文件收在“高级文件”中。这是显示层整理，不会从聊天中自动新增目标或改变目标状态。

文档默认以阅读方式显示公式，可切换“源文”查看文字原样。Markdown、TXT、Word 提取正文、LaTeX、研究目标及对话支持 `$…$`、`$$…$$`、`\(...\)` 和 `\[…\]`。LaTeX 还支持 equation、align、gather 等常见数学环境和前导区中的简单 newcommand / DeclareMathOperator 定义；正文改动定义的命令不做推测，相关公式显示源文。这是公式预览，完整论文排版仍以编译后的 PDF 为准。Word 的原生分数、上下标、根式、矩阵、求和等常见公式转换为 LaTeX 后显示；不支持的结构会明确标出，图片公式不做识别。普通公式须有明确标记，不猜测普通文字中的符号；Python、Lean 和配置文件保持源代码显示。渲染不改写原文件。

模型密钥只保存在 Node 进程内存中，不写入项目或应用配置。也可在启动进程的环境中提供 LLM_API_KEY、LLM_BASE_URL 和 LLM_MODEL_ID。不要把密钥写入版本控制中的文件。模型设置保存成功只说明配置保存，不代表模型请求成功。

可以添加多个服务配置，同一个服务也可以保存不同账号的配置。名称会自动填写，需要区分时再在“更多设置”修改。自定义服务支持“获取模型”，也可以在更多设置中手动填写；自动获取会略过名称明确标注为向量、排序、图片或语音的模型。这是对话候选列表，不是逐个模型调用的成功证明。

对话栏顶部仅显示当前模型名称；点击后展开服务和模型选项，选完模型自动收起，也可点击外部或按 Escape 关闭。无需返回设置即可切换。正在生成的回答保持启动时的服务和模型；后续提问使用新选择。历史回答显示实际使用的配置名称和模型。多个浏览器标签页各自发送界面中所选的配置，不借用其他配置的密钥。

旧单个配置会保留为第一个服务。环境变量密钥只用于这个默认配置，不会自动分配给新增服务；提供 LLM_BASE_URL 时还要求地址一致。已保存的选择不会被环境变量重置。新配置的密钥仍需在重启后重新填写，持久保存密钥不是本轮功能。

不配置密钥时仍能管理和阅读项目。重启后若没有通过环境提供密钥，需要重新填写。为保持项目边界，模型当前没有 shell、任意文件写入、网络检索或计算执行工具；它使用明确提供的文本上下文作答。

## 数据位置

- 添加的原始材料在 `workspace/project/materials/`。支持 PDF、Word（.docx）、Markdown、TXT、LaTeX、CSV、JSON/YAML、Python、Lean 和 BibTeX；单个最多 10 MB，每批最多 10 个。
- PDF 默认使用本地阅读器显示原始页面，可翻页和输入页码；也能切换到提取文字。Word 显示提取的正文，两者都保留下载原文件入口。上传不会立即将材料发给模型，只有选中并提问后才发送文本。
- PDF 提取最多读取开头 40 页、预览最多 200,000 字符。部分字体编码、扫描页、公式或表格不能准确还原；界面说明这些限制，不把图像当成已读文字。当前没有 OCR，模型使用提取文字及其节选，不直接读取 PDF 页面图像。
- 新笔记在 `workspace/project/notes/`，可由其他 coding agent 继续使用。
- 网页对话在项目的 `.co-math/web/conversation.json`，整体更新保存当前内容与运行状态。首次访问已有项目时会准备这个应用目录，并为 `.co-math/` 补上 Git 忽略规则；原材料不改写。忽略规则不影响已手动加入 Git 跟踪的文件。
- 已打开项目列表和非秘密模型设置在 Core 配置目录；新建项目仍沿用 Python Core 的布局。
- `CO_MATH_CONFIG_HOME` 可指定配置目录；`CO_MATH_PROJECTS_HOME` 可为这次网页运行指定项目目录，不会更改原 CLI 全局配置。CLI 可用 `--projects-home` 指向同一位置。
- 同一个配置目录仅运行一个服务实例，同一项目最多一个模型任务；同时最多三个项目请求。外部 agent 修改文件后点击“刷新材料”。

每次请求最长十分钟。对话接近存储容量时会在发送前提示整理已有记录；不自动删除旧对话。服务启动时把上次遗留的运行中回答标为中断，不重新执行或声称恢复供应商会话。

旧 CLI 的目标、工作流和审稿状态仍保留。网页对话和笔记不自动修改这些状态，因此网页中已有推导并不表示 CLI 中的研究目标已经完成。

## 当前范围

已实现项目、材料添加、PDF 原文阅读、文字提取、公式、真实模型对话、取消、对话保存、新笔记保存及 [VeryMath Skill 选择与流程指导](skills-integration.md)。独立数学审稿、论文综合、Skill 工具执行与 Electron 桌面发行尚未实现。

Python 和 Node 之间是固定方法的 JSON stdio 接口；没有新增文件哈希、审批凭证、冻结副本、接口描述注册或测试框架。路径和本机来源检查用于保护正常文件读写，不代表对恶意同权限本机进程的隔离。

数学回答属于研究草稿。实际任务中模型曾给出错误的不等号和多余的假设，经具体反馈后才得到修订稿；应用不会把生成成功标成证明验证成功。
